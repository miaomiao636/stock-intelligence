# 方向预测评估与运行诊断

本轮本地实现：2026-10-03。基于 `110e907`，尚未提交、推送或部署本轮修改。目标是让系统可以核验判断、解释未成交和暴露数据缺口，不是承诺提高胜率或盈利。

## 用户可以看到什么

- 交易总览和研究助手增加“运行与评估”：跟踪日期/样本质量、最近一批计划状态、方向正确率。
- 原因、统计口径和各观察窗口默认折叠。历史计划显示实际日期，不叫“今日成交”。
- 没有可核验结果时显示 `--`；方向预测与模拟账户盈亏分开。
- 只有文件可读取、不代表样本完整；行情错误、历史缺口和日线无法确定先后路径会单独提示。

## 如何形成一个可评估样本

1. 模型必须显式输出 `forecast_direction=up/down/flat` 与 `forecast_horizon_sessions=1..60`（整数）。提示词优先固定 5 个交易日，证据不足使用 `unknown/null`。不从目标价、交易动作或置信评分推断方向。
2. 盘前/盘中流水线在调用模型前复制行情输入，报告保存独立 `purpose=forecast_input` 证据。模型生成后为交易校验刷新的报价不能替换预测基准。旧报告没有该快照时保留原档案但不计分。
3. 判断须在上海日期同日、报告资料时点后 15 分钟内留档；基准价必须正数、时间可靠且不晚于判断。盘中报价最多早 15 分钟；盘前允许带明确时间的前收盘报价，保守最大跨度 14 个自然日。该跨度限制不是“已确认最近一个交易日”的证明，仍受数据源质量约束。
4. 原始证据、策略/提示词/模型/数据版本必须满足现有完整性门禁。新闻时间不完整也可能使整个报告不进入有效样本；不为增加样本数而回填时间、降低门禁或假装已验证。
5. 同股票、同上海日期、同观察期限只采用最早一条。后续改口不能增加成功样本；不同日期或期限仍可能重叠，不是独立试验。
6. 观察终点是**判断日之后第 N 个交易日的收盘**，不是持有 N 天、当日收盘、止盈止损价，也不要求先成交。

`confidence` 仍是未经校准的研究自评分，4 分不是 80% 上涨概率。

## 到期复核

入口为已有收盘任务，以及显式命令：

```sh
.venv/bin/python cli.py research review-maturity
```

该命令会使用现有 `TUSHARE_TOKEN` 访问 Tushare，追加研究复核与调度状态；不是只读命令。不会调用付费大模型、创建订单、修改持仓或调参。缺少数据库时不新建模拟账户。收盘 dry-run 和历史日期重跑跳过此步骤；当日缺少盘前报告不阻止独立到期复核。

数据要求：

- `trade_cal` 返回区间内完整的开市/休市日期；不使用周一到周五猜日历。
- `daily` 必须匹配证券与到期日期，不能用最新行情顶替历史收盘。
- `adj_factor` 必须覆盖基准日与到期日且因子有效。未核验时不评分；期间发生因子变化时，v1 不按原始价计算正确/错误。
- 初版支持 A 股，不把 ETF 等未支持证券算成成功或失败。
- 只允许 HTTPS，拒绝重定向；不会降级到 HTTP 或输出供应商原始异常/凭据。
- 单次任务最多 40 个外部请求，以 45 秒软预算限制发起新请求，单次请求 timeout 不超过 8 秒；在途请求与本地处理不构成严格墙钟 SLA。

结果只写研究表，判断和已核实标签不可变；缺失结果可以重试，已确认的结果不反复改写。运行受请求/时间预算限制，未完成的任务不是成功评分。

新增 `research_maturity_attempts` 保存每个判断/协议的最近尝试时间，仅用于公平调度，不是预测证据或结果。先固定最早判断的去重集合，再按未尝试优先、最久未尝试排序。相同不可判断结果仍推进尝试时间，但不重复制造复核档案；预算耗尽的未查询样本记为本批 `deferred_count`，不伪装成一次失败。回滚代码时可保留这张无交易数据的附加表，无需删除。

到期证据保留严格筛选后的基准日/终点日和复权因子数值，不只保存“已核验”的布尔标记。因除权暂不评分的样本也保留可追查数据。

官方接口定义：[交易日历](https://tushare.pro/document/2?doc_id=26)、[日线](https://tushare.pro/document/2?doc_id=27)、[复权因子](https://tushare.pro/document/2?doc_id=28)、[HTTP JSON 协议](https://tushare.pro/document/1?doc_id=40)。本轮仅验证合成适配器响应；真实账号权限、HTTPS 可用性和数据完整性仍需部署后验收，不能从文档或单元测试推定成功。

## 只读查询与指标

```sh
.venv/bin/python cli.py research scorecard
```

- `GET /api/research/scorecard`：已归档的全量方向成绩（不受 UI 列表的 30/100 条分页限制）。
- `GET /api/research/diagnostics`：跟踪质量、计划诊断与上述成绩。
- 诊断可接受 `trade_date=YYYY-MM-DD` 作为计划日期选择器：若没有当日计划，只展示不晚于该日期的最近归档计划。它不是整份响应的历史时点回测；跟踪/评分仍来自当前可读档案。

以上 GET 不初始化数据库、不拉行情、不调用模型、不执行交易。

| 指标 | 含义 |
| --- | --- |
| `evaluable` | 已得到有效正确/错误标签的去重样本数 |
| `accuracy_pct` | 正确数 / 可评估数；无样本为 null |
| `always_up_accuracy_pct` | 完全相同可评估样本中“始终预测上涨”的正确率 |
| `pending` | 尚未到期或尚未完成复核；不能直接解释为任务正常 |
| `unavailable` | 已尝试复核但缺失/不适用，未判定对错 |
| `excluded` | 未满足显式预测、输入证据、及时留档等要求 |
| `duplicate` | 同股票同日同期限后续重复判断 |
| `coverage_pct` | 可评估数 / 去重可登记数（含 pending/unavailable） |

正确率需要与覆盖率、样本数、同样本基线同时看。高于“始终上涨”基线只是初步描述，不证明扣费后有收益，更不证明样本外有效。没有真实成交，绝不补造账户收益。

## 跟踪可靠性改进

- 单一证券取价异常不会终止整批；行情形状、有限数字、OHLC 范围和目标日期均校验。
- 不用缺失 high/low 的 close 凑日线；无法评估时返回 `data_error` 和空收益。
- 兼容旧终态记录缺少衍生字段；文件名与内部日期不符时拒绝使用该快照。
- 文件完整性 `data_quality` 与样本可评估性 `tracking_quality` 分开；存在缺口时不生成看似精确的自动调参建议。
- 不删除坏文件，不自动补写缺失历史，也没有确认或修复服务器上曾出现的具体坏文件。

上线需单独授权：备份云端 SQLite 与配置、选择本轮源码/测试发布、核验原交易表不变，再确认真实收盘任务、日历/价格/因子权限与新样本流入。未知新闻时间可能使有效样本为零，必须修正数据溯源而不是放宽计分。
